# 优化二 · src/main.js 改动说明

> 学习对象：工作文件夹中的 `TEST`（"小小加法家"加法训练器，Vite + 原生 DOM）。
> 本轮范围：仅 `src/main.js`（题目状态与计时器管理、答对后禁用输入防重复提交与重复计分、过期回调校验、空答案 / 非法数值提示）。
> 不涉及 `src/style.css`，与"优化一"的样式改动完全兼容（DOM 结构、id 与 class 名保持原样）。

## 一、交付物

| 文件 | 说明 |
| --- | --- |
| `优化二/main.js` | 优化后的完整 `main.js`，可直接覆盖 `TEST/src/main.js` |
| `优化二/_verify/dom.test.mjs` | 行为验证脚本（最小 DOM 桩 + 假计时器），`node "优化二/_verify/dom.test.mjs"` |
| `优化二/说明.md` | 本文档 |

集成方式：把 `优化二/main.js` 复制为 `TEST/src/main.js`，然后在 `TEST` 下执行 `pnpm install && pnpm dev`。

## 二、原实现的问题

| # | 原实现（TEST/src/main.js） | 问题 |
| --- | --- | --- |
| 1 | 6 个模块级变量（`first`/`second`/`score`/`streak`/`questionId`/`nextQuestionTimer`/`isTransitioning`）各自散落 | 状态没有单一来源，`isTransitioning` 与 `questionId` 语义重叠，容易出现"改了变量忘了改视图" |
| 2 | 答对时先 `score += 1`，再 `isTransitioning = true`、禁用输入 | 判分与锁定之间存在可乘之机；锁定靠单一布尔位表达，语义不明确 |
| 3 | 过期回调只比较 `questionId` | 校验维度单一：题号相同但阶段已变（如换题后又回到同一题号）时无法拦截 |
| 4 | `<input ... required>` | 浏览器原生校验会先一步拦下空提交，**自定义的"先写下答案再提交哦！"提示根本不会出现** |
| 5 | `Number.isFinite(answer)` 作为合法性判断 | `1e3`、`1.5`、`-3` 都是有限数，会被当成合法答案送进判题分支，得不到"非法数值"提示 |
| 6 | 分数、连续数只在计分时写入 DOM | 初始视图与状态无关联，状态被重置时视图可能不同步 |

## 三、改动内容

### 1. 题目状态与计时器管理

- 新增单一状态对象 `state`：`first / second / score / streak / questionId / phase / nextQuestionTimer`，全流程只读写这一处。
- 引入显式阶段机 `state.phase`：
  - `'answering'`：正在作答，接受提交、可以计分；
  - `'locked'`：本题已答对并锁定，等待自动出下一题，拒绝任何重复提交。
- 计时器收敛为两个函数，句柄全局唯一：
  - `clearNextQuestionTimer()`：清空待执行计时器并置空句柄；
  - `scheduleNextQuestion(answeredQuestionId)`：先清理旧计时器再排队新的，回调执行时先把句柄置空。
- `newQuestion()` 与"换一道题"按钮都会先清理计时器，避免多个回调叠加出题。
- 新增 `renderScore()`，启动时与 `newQuestion()` 一起做初始渲染，视图始终由 `state` 输出。

### 2. 答对后禁用输入，防重复提交与重复计分

- 提交入口第一道守卫：`if (state.phase !== 'answering') return`，锁定阶段的一切提交（连点提交、回车、脚本触发）直接丢弃。
- 顺序调整为**先锁定、后计分**：`state.phase = 'locked'` 在 `score += 1` 之前执行，杜绝同一题被计两次分。
- 答对后 `setAnsweringEnabled(false)` 同时禁用输入框与提交按钮，`newQuestion()` 里再统一恢复，避免两处分别开关导致状态不一致。

### 3. 过期回调校验

```js
state.nextQuestionTimer = window.setTimeout(() => {
  state.nextQuestionTimer = null
  // 阶段已变（换题 / 重新作答）或题号已变 → 判定为过期回调，直接丢弃
  if (state.phase !== 'locked' || state.questionId !== answeredQuestionId) return
  newQuestion()
}, NEXT_QUESTION_DELAY)
```

- 双维度校验：**阶段 + 题号**。仅比较题号无法覆盖"答对 → 换题 → 又答对"后题号巧合相同的竞态。
- 计时器已被 `clearTimeout` 的情况与"回调已进入宏任务队列才被新题打断"的情况都能正确丢弃。

### 4. 空答案 / 非法数值提示

- 表单改为 `novalidate` 并去掉 `required`：把校验交回业务代码，自定义提示才能真正显示。
- 新增 `parseAnswer(inputEl)`，返回 `{ok:true,value}` 或 `{ok:false,reason:'empty'|'invalid'}`：
  - `inputEl.validity.badInput` 为真（浏览器无法解析输入）→ `invalid`；
  - 去空白后为空串 → `empty`；
  - 不匹配 `/^\d{1,6}$/`（小数、负号、科学计数法、字母、超长数字）→ `invalid`；
  - 全角数字 `１２３` 先归一化为半角再校验，照顾小朋友的输入法。
- `rejectAnswer(reason)` 分流提示：
  - 空答案 → "先写下答案再提交哦！"
  - 非法数值 → "请输入 0～999999 的整数答案哦！"
  - 同时设置 `aria-invalid="true"` 并重新聚焦、全选，便于直接改写。
- 判题语义保持合理：**纯数字但答错**（例如答案 20 却填 99）仍走"答错"分支，只重置连续数，不会被误判为非法输入。

## 四、验证记录

`优化二/_verify/dom.test.mjs` 用最小 DOM 桩 + 假计时器 + 固定随机数导入被测模块，逐项断言 47 条，覆盖 9 组场景：

| 场景 | 关键断言 |
| --- | --- |
| 1 初始状态 | 题面格式、分数/连续为 0、输入可用、只生成 1 道题 |
| 2 空答案 | 提示文案与 `try` 样式、`aria-invalid`、不计分、不锁定 |
| 3 非法数值 | `badInput` / `-3` / `1.5` / `1e3` / 7 位数字 / 字母 全部提示非法，不计分、不重置连续 |
| 4 答对 | 计分 +1、提示 `good`、输入与按钮双双禁用、挂起 1 个计时器 |
| 4 重复提交 | 锁定阶段再提交：分数不变、不新增计时器、不出新题 |
| 5 自动出题 | 题面更新、题号推进、输入恢复、计时器句柄释放 |
| 6 答错 | 连续归零、总分保留、保持可作答、不排队计时器 |
| 7 过期回调 | 答对后换题：旧回调被手动触发时被丢弃，不额外出题、不破坏题面 |
| 8 锁定中换题 | 计时器被清理，残留回调再次被丢弃 |
| 9 全角数字 | `１１` 作为数值 11 处理（答错），不误判为非法 |

实际运行结果：**47 项通过，0 项失败**；`node --check` 语法检查通过。

说明：`TEST` 为克隆仓库、本地无 `node_modules`，离线环境中无法拉取 `vite@5.4.21`，因此未执行 `pnpm build`；被测模块已按 ESM 实际导入并执行完整交互流程，语法与运行时行为均已验证。
